# reef-kh

珊瑚缸 KH 紀錄與分析。使用 HTML、CSS 與原生 JavaScript，不使用框架，也沒有任何外部套件。

## 功能

- 統計卡片：最新 KH、距離目標、近 7 天平均、目前添加量。
- KH 趨勢圖：每筆讀值、近 7 天平均線、目標線、換水標記、事件分隔線，可切換 30 天、90 天、全部。
- 每日添加量圖。
- 新增、編輯、刪除紀錄，可記錄測試方式、換水量與事件。
- 每日消耗量與建議添加量，會把換水的影響分開計算。
- Hanna 與 Salifert 兩種測試方式的同日比對。
- 匯出 JSON 與 CSV（可用 Excel 開啟）。
- 手機上像 App 一樣使用：底部分頁、首頁只要輸入 KH 就能儲存、自動同步到 GitHub、沒有網路也能開啟與記錄。

計算「每日 KH 消耗量」與「建議添加量」時使用，實際數值設定在 `js/config.js`，有變動時請兩邊一起更新。

| 項目 | 數值 | 說明 |
|---|---|---|
| 缸子實際水量 | 47 公升 | 整套系統的實際水量，採保守估算 |
| 添加劑濃度 | 每 100 L 添加 7 mL 原液，提高 0.18 dKH | 產品標示 |
| 稀釋比例 | 原液 170 mL＋RO/DI 580 mL，共 750 mL | 滴定機使用的是稀釋液 |
| 換算結果 | 1 mL 稀釋液約提高 0.0124 dKH | 以 47 L 計算的理論值 |
| 滴定機校準 | 2026-11-12 校準為每 1 mL 實出 1 mL | 校準前實測 0.8 至 0.9 mL，計算時以 85% 換算 |
| 新海水 KH | 8.3 dKH | 換水用的新海水實測值；換海鹽品牌或鹽度時重新測量，並更新 `NEW_SALTWATER_KH` |

- 添加劑品牌／品名：P. Ocean KH 添加液
- 目標 KH：8.3 dKH
- KH 測試方式：Hanna HI772 與 Salifert（每筆紀錄可各自標示）

## 在電腦上執行

不能直接雙擊 `index.html`，瀏覽器會擋下讀取 JSON 的動作，必須透過本機伺服器開啟。

1. 用 VS Code 開啟這個資料夾
2. 安裝擴充套件 Live Server
3. 在 `index.html` 上按右鍵，選「Open with Live Server」

## 在手機上使用

手機沒辦法連到電腦上的 Live Server，需要把網頁放到網路上。這個專案是純靜態網頁，可以用 GitHub Pages。

### 1. 開啟 GitHub Pages

1. 在 GitHub 的存放庫頁面，點「Settings」（設定）→ 左側「Pages」。
2. 「Source」（來源）選「Deploy from a branch」（從分支部署）。
3. 「Branch」（分支）選 `main`，資料夾選 `/ (root)`，按「Save」。
4. 等一到兩分鐘，頁面上方會出現網址，格式是 `https://<帳號>.github.io/reef-kh/`。

注意事項：

- 私人（private）存放庫要有付費方案才能使用 GitHub Pages；免費方案要先把存放庫改成公開（public）。
- 不論存放庫是否公開，Pages 的網站本身是公開的：知道網址的人都能看到頁面與 `data/kh-records.json` 裡的紀錄。頁面已加上 `noindex`，請搜尋引擎不要收錄。
- 想停止公開時，回到同一個設定頁按「Unpublish site」。

### 2. 加入主畫面

- iPhone：用 Safari 開啟網址 → 分享按鈕 →「加入主畫面」。
- Android：用 Chrome 開啟網址 → 右上角選單 →「加到主畫面」。

之後從主畫面的圖示開啟，沒有網址列，看起來就像一般的 App。

### 3. 設定 GitHub 同步

手機上新增的紀錄先存在手機裡，要靠權杖（token）才能存回存放庫。
點右上角的「設定」，裡面有產生權杖的步驟，重點是：

- 用瀏覽器開啟 `https://github.com/settings/personal-access-tokens/new`（手機版的 GitHub 選單裡找不到這個頁面）。
- 「Repository access」選「Only select repositories」，只勾這個存放庫。
- 「Permissions」按「＋」加入「Contents」，改成「Read and write」。
- 產生後那串文字只顯示一次，要立刻複製。
- 權杖只存在該裝置的瀏覽器裡，每台裝置各設定一次。iPhone 上，主畫面的 App 與 Safari 的儲存空間是分開的，要在主畫面的 App 裡設定。
- 權杖等同密碼，可以修改這個存放庫的檔案，不要提供給別人，也不要寫進專案。裝置遺失時到 GitHub 把它刪除。

### 4. 日常使用

手機版面底部有四個分頁：

| 分頁 | 內容 |
|---|---|
| 記錄 | 最新 KH、今天記錄了沒、KH 輸入框與「儲存」、最近的紀錄 |
| 趨勢 | 統計卡片、KH 趨勢圖、添加量圖 |
| 分析 | 消耗量與建議添加量、測試方式比較 |
| 歷史 | 所有紀錄，可編輯與刪除 |

- 每天只要在「記錄」輸入 KH 再按「儲存」。日期、添加量、測試方式會自動帶入，要改的話按「更多欄位」。
- 輸入框兩旁的「−」「＋」：第一次按會帶入上次的讀值，之後每按一次加減 0.1。
- 有設定權杖時，儲存後會自動同步到 GitHub，不用再按任何按鈕。
- 沒有網路時也能開啟並記錄，紀錄會先留在手機裡，恢復連線後自動送出。
- 「設定」裡有「重新載入」按鈕。從主畫面開啟時沒有重新整理的功能，程式更新後畫面沒變就按它。

## 新增、編輯與刪除紀錄

1. 新增：在表單輸入數值，按「新增」。
2. 編輯：在該筆紀錄按「編輯」，內容會帶入表單，修改後按「儲存修改」。
3. 刪除：在該筆紀錄按「刪除」。

這些變更會先暫存在瀏覽器的 localStorage，還沒有存進專案。儲存方式有兩種：

- 有設定權杖：預設會自動同步，變更直接提交到 `main` 分支（可在「同步與匯出」關閉自動同步，改成自己按「立即同步」）。之後電腦上的專案要更新時，在 VS Code 按同步（pull）即可。
- 沒有設定權杖：按「匯出 JSON」下載 `kh-records.json`，取代 `data/kh-records.json`，再用 VS Code 提交並同步。

兩種方式擇一使用。已經用 GitHub 同步的話，就不要再手動取代資料檔，以免覆蓋掉較新的內容。

多台裝置同時使用時的規則：

- 同一筆紀錄在兩台裝置都修改過，以後同步的那一台為準。
- 同一筆讀值在兩台裝置各輸入了一次（內容完全相同），只會保留一筆。
- 讀不到 GitHub 時，網頁會改用網站上的資料檔並顯示提醒；這時尚未同步的變更會原封不動保留，等連線恢復再同步。
暫存的變更只存在同一台裝置的同一個瀏覽器，清除瀏覽資料就會消失。儲存前，可按「捨棄未儲存的變更」回到資料檔裡的內容。

## 離線使用與更新

- 正式網站（https）會啟用服務工作線程（service worker），把網頁的檔案存一份在裝置裡。本機開發（Live Server）不會啟用。
- 採「網路優先」：有網路時一律向伺服器要最新的檔案，所以程式更新後重新開啟就是新版；沒網路才使用存下來的那一份。
- 有設定權杖時，每次成功讀到 GitHub 上的資料，也會在裝置裡存一份備份。離線時顯示的是這份備份，並會提示目前不是最新資料。
- 對 GitHub 的連線（讀寫資料檔）不經過服務工作線程，也不會被快取。
- 新增 JS、字體等檔案時，要記得把檔名加進 `sw.js` 的 `CORE_FILES`，否則第一次安裝後離線開啟會缺檔。

## 資料格式

`data/kh-records.json` 是一個陣列，一筆紀錄一行，欄位如下：

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | 字串 | 這筆紀錄的識別碼，不可重複。由網頁自動產生；手動加一行時可以省略，網頁會自動補上 |
| `date` | 字串 | 日期，格式 `YYYY-MM-DD` |
| `time` | 字串 | 測量時間，格式 `HH:MM`，沒記就是 `""` |
| `kh` | 數字 | KH 值，單位 dKH |
| `dose_ml` | 數字或 `null` | 當時滴定機的每日添加量設定，單位 mL |
| `type` | 字串 | `"tank"` 魚缸水，`"standard"` 標準液驗證 |
| `method` | 字串 | 測試方式：`"hanna"`、`"salifert"`、`"other"`，沒標示就是 `""` |
| `exclude` | 布林 | `true` 表示異常或可疑讀值，不納入統計，圖上以 × 標示 |
| `water_change_l` | 數字或 `null` | 當天的換水量，單位公升 |
| `water_change_timing` | 字串 | 這筆讀值是換水 `"before"` 前、`"after"` 後測的；沒註明是 `""`，計算時視為換水後 |
| `event` | 字串 | 事件，例如 `"滴定機校準"`，圖上會畫出分隔線 |
| `note` | 字串 | 備註 |

同一天有多筆紀錄標示換水量時，視為同一次換水，不會重複計算。

網頁用 `id` 來認紀錄，而不是用內容。這樣即使兩筆紀錄的內容一模一樣（例如連續兩天讀值相同），修改或刪除時也不會弄錯對象。

## 統計規則

- 目標 KH 為 8.3 dKH，設定在 `js/config.js` 的 `TARGET_KH`。
- 標準液讀值與 `exclude` 為 `true` 的讀值不納入統計，但仍會顯示在表格中。
- 同一天有多筆有效讀值時，取平均作為當天的 KH。
- 換水日如果換水前後都有讀值，當天的 KH 取換水後的平均。
- 趨勢線是「近 7 天平均」：當天往前 7 天內所有測量日的平均，至少要有 3 天才畫。

## 消耗量的算法

KH 的變化來自三件事：添加劑補充、換水、缸子消耗。

- 添加劑：每天補充「添加量 × 每 mL 的效果」。2026-11-12 校準前的添加量是設定值，計算時乘上 85% 換算成實際出水量。
- 換水：換掉一部分的水，KH 會往新海水的 KH 靠近。
  換水後 KH = 換水前 KH + 換水比例 ×（新海水 KH − 換水前 KH）。
- 消耗：把每個觀測值減掉累計的添加劑補充量與換水變化，再用最小平方法求出下降的斜率，就是每日消耗量。

建議添加量：

- 維持某個 KH 所需的添加量 =（每日消耗量 − 換水在那個 KH 平均每天補充的量）÷ 每 mL 的效果。
- 缸子的 KH 越接近新海水，換水補充得越少，所以到達目標之後的維持量會比現在高。
- 換水量以最近 28 天的平均計算，假設之後維持相同的換水習慣。

估計範圍包含三種不確定性：測量誤差、校準前出水比例（80% 至 90%）、新海水 KH 的推算範圍。
補充量依產品標示換算，是理論值；所有結果都是估算，僅供調整添加量時參考。
